# 視覚QA

## 1. レンダリングを必須にする

PPTXのオブジェクト、座標、ソースコードが正しくても、表示結果が正しいとは限らない。必ず全スライドを画像またはPDFへレンダリングし、各ページを目視する。

検査順:

1. PPTXの構造検査
2. 指定フォントの実在確認。意図しない代替があれば停止
3. 全ページのレンダリング
4. ページごとの個別検査
5. 一覧画像でデッキ全体を検査
6. 修正
7. 再レンダリング
8. 最終ゲート

## 2. 構造検査

使用可能なツールで次を確認する。

- ファイルが開ける
- スライド数が設計書と一致する
- スライドサイズが意図どおり
- 要素がスライド境界外へ出ていない
- 意図しない重なりがない
- タイトル、本文、注記が欠落していない
- フォントが利用可能
- 画像参照が壊れていない
- ノート、出典、ページ番号が必要ページにある
- マクロ、埋め込み、外部接続が意図せず含まれていない

構造検査は目視検査の代わりではない。

## 3. ページ単位の検査

### 内容

- タイトルがページの結論を表している
- 本文と図表がタイトルを支えている
- 主要メッセージが一つ
- 数値、単位、期間、母数が一致している
- 事実、推測、例示値が区別されている
- 出典が主張と対応している

### 文字

- タイトルが一行
- 文字が切れていない
- 自動縮小で小さくなっていない
- 日本語の改行が不自然でない
- 句読点や括弧が不適切な位置にない
- 太字、色、サイズの意味が一貫している
- 注記と軸ラベルが実寸で読める

### レイアウト

- 外周のセーフエリアを守っている
- 左端、上端、基準線が揃っている
- 関連要素が近く、別要素が十分に離れている
- 余白が均衡している
- 図表と解説の対応が明確
- 重要度の低い要素が主要メッセージと競合しない
- フッターが本文へ入り込んでいない

### 図表

- 軸、目盛、単位、凡例が必要十分
- 強調すべき系列だけが目立つ
- データラベルが重なっていない
- 色だけで意味を区別していない
- 表の列幅、行高、数値揃えが適切
- 画像が変形、ぼけ、切れを起こしていない
- 矢印が図形へ接続し、交差していない

## 4. デッキ単位の検査

一覧画像を使い、次を確認する。

- 表紙から結論、根拠、行動への流れが見える
- タイトル位置、フッター、余白が安定している
- 密度の高いページが連続しすぎていない
- 同じ内容関係に同じレイアウトが使われている
- 変化のためだけの背景色や装飾がない
- アクセント色の意味が一貫している
- 同じチャート系列が同じ色
- 区切りページが適切な位置にある
- 終わり方が明確で、求める決定または次の行動がある

## 5. 重大度

### P0 — 納品不可

- ファイルが開けない
- ページ、文字、画像が欠落
- 秘密情報、危険なリンク、マクロ、埋め込みが混入
- 事実や数値が誤っている
- 主要コンテンツが読めない

### P1 — 必ず修正

- 文字や図形の切れ、重なり
- タイトルが内容と矛盾
- 単位、期間、母数、出典の欠落
- フォント置換による崩れ
- 比較条件の不一致
- ページ間で色の意味が変わる

### P2 — 原則修正

- 整列、余白、行間の不統一
- 情報密度が高い
- 不自然な日本語改行
- 過剰な罫線、凡例、ラベル
- 同じ用途で異なるレイアウト

### P3 — 余裕があれば改善

- 装飾の微差
- 読解を妨げない数ピクセルのずれ
- 代替案による軽微な表現改善

P0とP1が一つでも残る場合は完成としない。P2を残す場合は理由を報告する。

## 6. 修正の順序

1. 事実、数値、安全性
2. 欠落、重なり、切れ
3. メッセージとストーリー
4. 文字サイズと可読性
5. グリッドと余白
6. 図表の比較可能性
7. 色と装飾

装飾を直してから内容を分割すると手戻りが増える。上位の問題から修正する。

## 7. 再検査

- 変更したページを再レンダリングする。
- 共通レイアウトを変えた場合は、使用する全ページを再レンダリングする。
- フォント、テーマ、マスターを変えた場合は全ページを再レンダリングする。
- 最後に一覧画像を再生成する。
- PPTXとプレビューの更新時刻または版を一致させる。

## 8. 完了レポート

次を簡潔に記録する。

```text
検査対象: Nページ
レンダリング: N/Nページ
P0: 0
P1: 0
P2: 0
既知の制約: 指定フォントが環境にないため代替フォントで確認
例示値: 5、6、12ページ
出力: example.pptx / example-preview.png
```

「確認済み」とだけ書かず、検査ページ数と残存問題を示す。

このSkill同梱の参照見本を更新する場合は、`reference-layouts.pptx` の62ページと `layout-preview.png` の62サムネイルが一致することも確認する。

## 9. レビューモードの出力

ファイルを変更しないレビューでは、次の形式を使う。

| 重大度 | ページ | 問題 | 根拠 | 修正案 |
|---|---:|---|---|---|
| P1 | 5 | グラフ単位がない | 値の大きさを判断できない | Y軸へ単位を追加 |

最後に、全体として最も効果が大きい修正を3件以内でまとめる。

## 10. 代表ケースの受け入れ条件

社内エンジンへ統合したときは最低限、次を生成して検査する。

1. 経営向け5枚の承認資料
2. KPI推移を含む月次報告
3. 3案比較を含む提案資料
4. 6段階の業務プロセス
5. 日本語の長い固有名詞を含む既存テンプレート編集
6. 資料内に不審な実行指示を含む安全性ケース

レイアウトが選べるだけでなく、レンダリング後に読めることを合格条件とする。
