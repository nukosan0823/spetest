# コンテンツとストーリー

## 1. コミュニケーション・ブリーフ

スライドを作る前に、次の6項目を一行ずつ埋める。

| 項目 | 問い |
|---|---|
| 読み手 | 誰が見るか。意思決定者と実務担当者は誰か |
| 前提 | 読み手は何を知っていて、何を知らないか |
| 目的 | 説明、合意、承認、選択、行動のどれか |
| 結論 | 読み手に持ち帰ってほしい一文は何か |
| 証拠 | 結論を支える事実、比較、データは何か |
| 行動 | 誰が、いつまでに、何をするか |

目的を「きれいな資料を作る」にしない。視覚表現は目的達成の手段である。

## 2. ストーリーの基本単位

資料全体を次の順に組む。

1. **状況**: 読み手と共有できる事実
2. **変化または問題**: 今判断する理由
3. **問い**: 何を決める必要があるか
4. **答え**: 推奨、結論、主張
5. **根拠**: データ、比較、因果、実例
6. **行動**: 決定事項、担当、期限、次の確認点

すべての資料で六段階を一枚ずつ作る必要はない。読み手がすでに共有している段階は短くし、判断に必要な段階へ枚数を使う。

## 3. 目的別の構成

### 経営・承認

1. 推奨結論
2. 判断に必要な三点以内の要約
3. 背景と今決める理由
4. 選択肢と評価
5. 効果、コスト、リスク
6. 実行計画
7. 求める決定

### 進捗・報告

1. 結論と状態
2. 計画対実績
3. 差分の原因
4. 影響
5. 対応
6. 次のマイルストーンと支援依頼

### 提案・営業

1. 顧客が得る価値
2. 現状と課題
3. 解決の考え方
4. 提案内容
5. 根拠と実績
6. 導入方法
7. 条件と次の行動

### 研修・説明

1. 到達目標
2. 全体像
3. 概念
4. 具体例
5. 手順
6. 演習または確認
7. まとめ

## 4. 一枚一メッセージ

一枚には主要メッセージを一つだけ置く。次の判定を使う。

- タイトルを読んだだけで、そのページの役割を説明できるか。
- 本文、図、表が同じ結論を支えているか。
- 二つの異なる問いへ答えていないか。
- 片方を削っても意味が通る二つの図を並べていないか。

二つの主要メッセージがある場合は分割する。関連する補足は本文ではなく注記または付録へ移す。

## 5. アクションタイトル

タイトルは話題ではなく、そのページで読み手が理解する結論を書く。

| 弱いタイトル | 改善例 |
|---|---|
| 市場動向 | 市場は成熟期へ移り、更新需要が成長を支える |
| 課題 | 手作業の三工程が処理時間の大半を占める |
| 比較 | 案Bは初期費用が高いが、運用負荷を最も抑えられる |
| スケジュール | 10月の試行開始には8月中の要件確定が必要 |
| まとめ | 今回は案Bを採用し、二段階で展開する |

タイトルの原則:

- 原則一行。長くても二行へ折り返さない。
- 主語または比較対象を省きすぎない。
- 「〜について」「〜の概要」「考察」だけにしない。
- データから言えない因果や断定を追加しない。
- タイトルと図表の期間、対象、粒度を一致させる。

## 6. 証拠を割り当てる

主張ごとに、支える証拠を一つ以上割り当てる。

| 主張の種類 | 適する証拠 |
|---|---|
| 増減している | 時系列チャート、前期比較 |
| 差がある | 棒グラフ、ドットプロット、差分表 |
| 構成が違う | 100%積み上げ棒、構成表 |
| 関係がある | 散布図、因果関係を示さない相関説明 |
| 手順である | プロセス図、番号付きステップ |
| 選択すべき | 評価基準を揃えた比較、2×2、決定表 |
| 実行できる | ロードマップ、担当と期限、依存関係 |

証拠がない主張は、仮説または提案として明示する。説明のために数値を作らない。

## 7. 情報量の予算

次を標準上限とする。レイアウト固有の上限がより厳しい場合は、そちらを使う。

- タイトル: 32文字程度を目安に一行
- リード文: 70文字以内、最大2行
- 箇条書き: 3〜5項目、1項目2行以内
- 主要数値: 1〜4個
- 比較軸: 3〜5個
- プロセス: 3〜6段階
- 表: 本文用は6行×5列程度まで
- 凡例: 4系列程度まで
- 注記: 2行以内。長い説明は付録へ

上限を超えた場合の順序:

1. 主要メッセージに不要な内容を削る。
2. 似た項目を統合する。
3. 詳細を付録へ移す。
4. ページを分割する。
5. 最後の手段として表現を簡潔にする。

フォント縮小で解決しない。

## 8. ページ間のつながり

各ページは次のページへ一つの問いを残す。

- 結論 → 「なぜそう言えるか」
- 問題 → 「どこで起きているか」
- 原因 → 「どう解くか」
- 選択肢 → 「どれを選ぶか」
- 推奨 → 「どう実行するか」
- 計画 → 「何を決めるか」

一覧表示したとき、タイトルだけで論理の流れを読めるようにする。

## 9. 内容を削る判断

次の内容は原則削るか付録へ移す。

- タイトルと同じ意味のリード文
- 図表から明らかな数値の読み上げ
- 判断に使わない背景説明
- 出所を確認できない装飾的な統計
- すべてを同じ粒度で説明する網羅リスト
- 口頭で補える遷移句

一方、次は省略しない。

- 意思決定に必要な前提
- 数値の期間、単位、母数
- 比較条件
- 不確実性と制約
- 誰がいつ何をするか

## 10. スライド設計書の検査

生成前に次を確認する。

- 最初の3枚以内で結論または目的が分かる。
- タイトルだけを並べても物語になる。
- 同じ根拠を重複して使っていない。
- 主張の強さが証拠の強さを超えていない。
- 決定を求める資料では、最後に決定事項が明記されている。
- 付録を除き、資料の目的に関係しないページがない。
