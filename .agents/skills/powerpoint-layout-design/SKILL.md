# PowerPointレイアウト・デザイン

内容の正確性と既存テンプレートを守りながら、読み手が短時間で結論、根拠、次の行動を理解できるスライドを設計する。

このファイルは、日本語で管理できる単一ファイル完結型の移植バンドルでもある。通常のスライド作成・編集では「実行モード」、既存資料の診断だけを求められた場合は「レビューモード」、このファイル全体が社内AIのチャットへ貼り付けられた場合は「移植モード」として扱う。

## 規範語

本文では次の意味で規範語を使う。

- **必須**：満たさなければ完了とみなさない。
- **原則**：特別な理由がない限り守る。外した場合は理由を説明できるようにする。
- **任意**：目的に合う場合だけ採用する。
- **禁止**：ユーザーが明示的に求め、かつ内容の正確性や可読性を損なわない場合を除いて行わない。

`PPTD-`で始まる識別子は移植時の欠落検査に使う。文言を社内環境へ合わせて変更しても、規則の意味と識別子は保持する。

## モードを判定する

- **PPTD-001 実行モード**：PowerPointの作成、編集、再設計、レイアウト改善、図表調整、テンプレート適用を依頼された場合に選ぶ。
- **PPTD-002 レビューモード**：問題点の指摘、デザイン評価、改善案だけを依頼された場合に選ぶ。ユーザーが修正も求めていない限り、ファイルを書き換えない。
- **PPTD-003 移植モード**：このファイルが既存の社内PowerPoint作成Skillへ反映する素材として貼られた場合に選ぶ。「社内ローカルAIによる統合・分割手順」に従う。
- **PPTD-004 複合モード**：診断後に修正する依頼では、レビューモードで問題を特定してから実行モードへ進む。

## 規則の優先順位

規則が衝突するときは、次の順序で優先する。

1. **PPTD-010** ユーザーが指定した目的、対象読者、内容、事実、数値、引用、機密区分
2. **PPTD-011** 既存の会社テンプレート、スライドマスター、レイアウト、ブランド規程、アクセシビリティ規程
3. **PPTD-012** 配布、投影、印刷、オンライン閲覧などの利用条件
4. **PPTD-013** 意思決定に必要な論理、証拠、情報階層、可読性
5. **PPTD-014** 本文のレイアウト・デザイン原則
6. **PPTD-015** 装飾上の好み

下位の規則を守るために、上位の情報を削除、改変、捏造しない。既存テンプレートがある場合、本文の数値的な目安よりテンプレートの書式を優先する。ただし、文字切れ、判読不能、誤解を招く図表、重大なコントラスト不足は、テンプレート由来でも修正候補として明示する。

## 非コピー境界と由来

このSkillは、一般的なプレゼンテーション設計の知見と、公開リポジトリ「Mck-ppt-design-skill」で示されているレイアウト・デザイン上の考え方を参考に、社内利用向けに日本語で独自再構成したものである。

- **PPTD-020** 参照元の文章、コード、プロンプト、設定、画像、テンプレート、ロゴ、図版、フォントファイルを複製しない。
- **PPTD-021** 参照元固有のエンジン名、API、ディレクトリ構成、座標値、色値、フォント指定を移植しない。
- **PPTD-022** 特定企業または特定ブランドになりすます名称、配色、ロゴ、表現を使わない。
- **PPTD-023** 取り込む対象を、レイアウト選択、情報階層、余白、整列、チャート、画像、視覚QAなどの抽象的な設計原則に限定する。
- **PPTD-024** 社内テンプレート、社内ブランド、既存PowerPoint生成エンジンを実装上の正本とする。
- **PPTD-025** 外部資料を追加参照した場合は、許諾、ライセンス、出典、取得日を社内ルールに従って記録する。

参考URL：<https://github.com/likaku/Mck-ppt-design-skill>

## 作業開始時に確認する

依頼文と提供物から、次を判定する。

- **PPTD-030** 資料の目的：説明、承認、意思決定、提案、報告、教育、議論のいずれか。
- **PPTD-031** 対象読者：役職、専門性、前提知識、関心、反対理由。
- **PPTD-032** 読了後に期待する行動：承認、選択、理解、記憶、実行。
- **PPTD-033** 利用条件：投影、PC閲覧、印刷、配布、読み上げ、オンライン会議。
- **PPTD-034** 画面比率、ページ数、提出形式、締切。
- **PPTD-035** 既存PPTX、スライドマスター、会社テンプレート、ブランドガイドの有無。
- **PPTD-036** 保持必須の事実、数値、表、グラフ、引用、注記、ロゴ、法務文言。
- **PPTD-037** 使用可能な画像、アイコン、データ、出典。

結果を大きく変える情報が欠ける場合だけ確認する。確認できないまま進められる場合は、最小限の仮定を置き、最終報告で明示する。会社名、実績値、顧客名、調査結果などを推測で追加しない。

## 全体ワークフロー

次の順序で実行する。見た目から作り始めない。

1. **PPTD-040 目的を固定する**：対象読者、意思決定、読後行動、利用条件を一文ずつ定義する。
2. **PPTD-041 提供物を検査する**：既存PPTX、テンプレート、ブランド、データ、画像、引用を確認する。
3. **PPTD-042 内容を固定する**：事実、数値、出典、未確定事項、変更禁止要素を一覧化する。
4. **PPTD-043 ストーリーを設計する**：問い、結論、根拠、含意、行動の順序を決める。
5. **PPTD-044 タイトルだけを通読する**：各スライドのタイトルを並べ、タイトルだけで論旨が通るように直す。
6. **PPTD-045 情報量を見積もる**：要素数、文字量、系列数、カテゴリ数、注記量を数え、分割の必要性を判断する。
7. **PPTD-046 レイアウトを選ぶ**：伝達目的に合うレイアウトを「レイアウト選択表」から選ぶ。
8. **PPTD-047 視覚システムを定義する**：テンプレートから書体、色、余白、罫線、強調、フッターを取得する。
9. **PPTD-048 実装する**：マスターとレイアウトを維持し、要素を整列させ、内容を配置する。
10. **PPTD-049 レンダリングする**：全スライドを画像として書き出す。
11. **PPTD-050 視覚QAを行う**：各ページを原寸相当で確認し、一覧表示で全体の流れを確認する。
12. **PPTD-051 修正ループを回す**：原因となる内容または生成元を修正し、再レンダリングする。
13. **PPTD-052 完了条件を確認する**：内容、レイアウト、テンプレート、出典、QAを満たした場合だけ納品する。

## ストーリーと一枚一メッセージ

- **PPTD-060** 一枚につき、読み手が持ち帰る主メッセージを一つに絞る。
- **PPTD-061** タイトルは原則としてトピック名ではなく、結論、変化、示唆、判断を表す文にする。
- **PPTD-062** タイトル、主要ビジュアル、根拠、注記の順に視線が流れるようにする。
- **PPTD-063** 各スライドを「問い → 答え → 根拠 → 含意または行動」のどこに置くか説明できるようにする。
- **PPTD-064** 隣接するスライドの関係を、追加、対比、因果、分解、時系列、具体化のいずれかで説明できるようにする。
- **PPTD-065** タイトルだけを読んだときに、重複、飛躍、逆戻りがないか確認する。
- **PPTD-066** 重要な例外や前提は隠さず、結論の近くに短く置く。詳細は注記または別ページへ移す。
- **PPTD-067** タイトルページと章扉は最小限にし、本文の説明を詰め込まない。
- **PPTD-068** スライド上に制作メモ、プロンプト、レイアウト名、内部向け判断過程を表示しない。

## 情報階層を設計する

原則として、次の階層を視覚的に区別する。

1. **PPTD-070 主メッセージ**：スライドタイトルまたは大きな結論。
2. **PPTD-071 主要証拠**：チャート、表、数値、図、画像、比較。
3. **PPTD-072 解釈**：証拠が何を意味するかを示す短い文。
4. **PPTD-073 補助情報**：条件、定義、凡例、期間、単位。
5. **PPTD-074 出典と注記**：検証可能性を保つための情報。

階層ごとに書体サイズ、太さ、色、位置、余白のうち複数を同時に変えすぎない。重要度を示すために、すべてを太字、アクセント色、囲み枠にしない。

## グリッド、余白、整列

- **PPTD-080** すべてのページで左右の基準線、タイトル開始位置、本文開始位置、フッター位置を統一する。
- **PPTD-081** 要素は見えないグリッドへ揃える。数ピクセルまたは数ポイントの偶然のずれを残さない。
- **PPTD-082** 外周余白、セクション間余白、要素内余白の三段階を区別する。
- **PPTD-083** 同じ論理階層にある要素は、同じ幅、高さ、開始位置、間隔を原則として共有する。
- **PPTD-084** 左揃えを基本とし、中央揃えはタイトルページ、章扉、単一メッセージなど意図が明確な場合に限る。
- **PPTD-085** 余白は「空き」ではなく、情報のまとまりと優先順位を示すために使う。
- **PPTD-086** スライドの片側だけに意図しない大きな空白を残さない。非対称構図では視覚的な重心を確認する。
- **PPTD-087** 囲み枠を増やして整列不足を隠さない。まず位置、幅、余白、見出しでグループ化する。
- **PPTD-088** ページ番号、機密区分、出典、ロゴは本文より弱く見せ、位置を統一する。

## 視覚トークン

具体値を固定する前に、既存テンプレートから役割ベースのトークンを抽出する。

| トークン | 役割 |
|---|---|
| `background` | ページ背景 |
| `surface` | 必要最小限の面、表のヘッダー、注記領域 |
| `text-primary` | タイトルと本文 |
| `text-secondary` | 補足、単位、注記 |
| `accent-primary` | 最重要の強調、選択肢、主要系列 |
| `accent-secondary` | 二次的な比較または補助系列 |
| `positive` | 改善、達成、承認 |
| `warning` | 注意、未確定、期限接近 |
| `negative` | 悪化、重大リスク、未達 |
| `grid-line` | 表、軸、区切りの弱い線 |

- **PPTD-090** 色をRGB値の羅列ではなく、意味を持つ役割として管理する。
- **PPTD-091** 主要アクセントは原則一色とし、追加色は比較または意味区分に必要な場合だけ使う。
- **PPTD-092** 同じ意味には同じ色を使い、同じ系列の色をページ間で変えない。
- **PPTD-093** 赤と緑だけで状態を区別しない。文字、記号、形状を併用する。
- **PPTD-094** 文字と背景、線と背景、データ系列同士のコントラストを実際の表示条件で確認する。
- **PPTD-095** グラデーション、立体表現、強い影、光彩、質感は原則として使わない。
- **PPTD-096** 企業テンプレートが色を定めている場合、その意味体系を優先し、独自パレットを混ぜない。

## 日本語タイポグラフィ

- **PPTD-100** テンプレート指定の日本語フォントを最優先する。指定がない場合は、利用環境で確実に表示できる可読性の高い日本語書体を選ぶ。
- **PPTD-101** 欧文フォントだけを設定して完了とせず、東アジア文字に適用されるフォントを確認する。
- **PPTD-102** タイトル、見出し、本文、注記の四段階を原則とし、過剰なサイズ種類を作らない。
- **PPTD-103** 同じ階層では、書体、サイズ、太さ、色、行間を揃える。
- **PPTD-104** タイトルは原則一行に収める。長い場合は、文字を縮小する前に結論を短くする。
- **PPTD-105** 本文が収まらない場合は、要約、分割、レイアウト変更の順で対処し、極端な縮小を最後の手段にする。
- **PPTD-106** 助詞、約物、括弧、単位、数値が不自然な位置で改行されていないか、レンダリング画像で確認する。
- **PPTD-107** 手動改行は意味の切れ目に置く。編集後に語が増減しても不自然にならないか再確認する。
- **PPTD-108** 行間と段落間を区別する。箇条書きの各項目が一つの塊として読めるようにする。
- **PPTD-109** 全角と半角、句読点、括弧、数字、単位、英字略語の表記を資料内で統一する。
- **PPTD-110** 数字を比較する表やKPIでは桁、単位、小数点、符号、期間を揃える。
- **PPTD-111** 投影資料では、離れた位置から読める大きさを優先する。配布資料でも小さな文字へ情報を押し込まない。
- **PPTD-112** フォントサイズの既定値は生成エンジンまたはテンプレートに従う。指定がない場合は、タイトル、見出し、本文、注記の差が明確になる階層を設定し、実表示で検証する。

## レイアウトを選択する

最初に伝達目的を選び、次に情報量を確認する。見た目の好みだけでレイアウトを選ばない。

| 伝達目的 | 第一候補 | 代替 | 避ける構成 |
|---|---|---|---|
| 一つの重要数値を記憶させる | ビッグナンバー | 数値＋短い根拠 | 小さなKPIカードの乱立 |
| 2〜4個の指標を俯瞰する | KPIストリップ | 小型チャート併記 | 5個以上を同じ強さで並べる |
| 複数案を比較する | 横並び比較 | 評価表 | 文章だけの二段組 |
| 変更点を示す | Before／After | 差分表 | 二つの独立説明に見える配置 |
| 順番を示す | ステップ／プロセス | 縦型手順 | 矢印だけで因果まで表す |
| 日付と節目を示す | タイムライン | ロードマップ | 時間軸のないカード列 |
| 全体の流れを示す | バリューチェーン | スイムレーン | 接続関係が曖昧な箱の集合 |
| 二軸で分類する | 2×2マトリクス | 散布図 | 軸の定義がない四象限 |
| リスクを示す | リスクマトリクス | リスク一覧 | 色だけの重大度表現 |
| 時系列変化を示す | 折れ線 | 縦棒 | 円グラフの複数時点比較 |
| 大小や順位を示す | 横棒 | ドットプロット | 項目名が読めない縦棒 |
| 構成比を示す | 積み上げ棒 | ドーナツ | 区分が多い円グラフ |
| 増減の橋渡しを示す | ウォーターフォール | 差分棒 | 合計との関係がない増減矢印 |
| 相関を示す | 散布図 | バブル | 二軸尺度が異なる折れ線 |
| 正確な値を参照させる | データ表 | 表＋示唆 | 装飾的なグラフへの置換 |
| データと解釈を同時に示す | 表／チャート＋インサイト | 注釈付きチャート | 説明文が図から離れた配置 |
| 事例や証拠を示す | ケーススタディ | 画像＋要点 | 出典のない装飾写真 |
| 提案を締める | 推奨事項＋次の行動 | 意思決定ページ | 抽象的な「まとめ」だけ |

## レイアウト・カタログ

### 導入とナビゲーション

#### タイトルページ

- **PPTD-120** タイトル、必要な副題、日付、組織名だけを基本とする。
- **PPTD-121** キービジュアルを使う場合は、文字とのコントラストとトリミングを優先する。
- **PPTD-122** 本文の要点、長い説明、複数ロゴを詰め込まない。

#### 章扉

- **PPTD-123** 章名と、その章で答える問いまたは短いメッセージを置く。
- **PPTD-124** 本文ページより余白を広くし、資料全体の区切りを明確にする。
- **PPTD-125** 章番号、色帯、画像などの区切り表現を資料全体で統一する。

#### アジェンダ／ナビゲーター

- **PPTD-126** 項目数は読み手が一度に把握できる範囲へ絞る。
- **PPTD-127** 現在地を示す場合は、強調色または太さの一要素で示す。
- **PPTD-128** 各本文ページへ大型ナビゲーションUIを常設しない。必要なら小さな章表示にする。

### 要約とメッセージ

#### エグゼクティブサマリー

- **PPTD-130** 結論、主要根拠、必要な判断、次の行動を優先順に並べる。
- **PPTD-131** すべての章を均等に要約せず、意思決定に必要な項目へ絞る。
- **PPTD-132** 3〜5個程度の論点を上限の目安とし、超える場合はページを分ける。

#### キーテイクアウェイ

- **PPTD-133** 一つの結論と、その結論を支える最小限の根拠を置く。
- **PPTD-134** 余白と文字階層で主張を強調し、巨大な引用符や装飾記号に依存しない。

#### ビッグナンバー

- **PPTD-135** 数値、単位、期間、比較基準を一体として表示する。
- **PPTD-136** 数値の意味を一文で明示する。
- **PPTD-137** 精度が不要な場合は過剰な小数桁を削る。

#### KPIストリップ

- **PPTD-138** 指標は原則2〜4個に絞り、同じ書式で比較できるようにする。
- **PPTD-139** 実績、計画、前年差など、比較の種類を混在させる場合はラベルを明示する。
- **PPTD-140** すべての指標を同じアクセント色で強調しない。最重要指標だけを強くする。

### 比較と選択

#### 横並び比較

- **PPTD-141** 比較対象は原則2つ、必要に応じて3つまでとする。
- **PPTD-142** 同じ評価軸を同じ順序で並べ、面積と情報量を揃える。
- **PPTD-143** 推奨案がある場合は、理由とともに一段階だけ強く見せる。

#### Before／After

- **PPTD-144** 左右または上下で時間方向を一貫させる。
- **PPTD-145** 変更前後の差分が同じ観点で読めるようにする。
- **PPTD-146** 改善を示すためだけに色、尺度、写真サイズを恣意的に変えない。

#### 選択肢評価表

- **PPTD-147** 評価軸の定義、重み、記号の意味を示す。
- **PPTD-148** 評価結果だけでなく、判断に効いた差を示す。
- **PPTD-149** 精密に見える点数を根拠なく作らない。

### プロセスと時間

#### ステップ／プロセス

- **PPTD-150** 原則3〜5段階とし、各段階の粒度と文法を揃える。
- **PPTD-151** 順番だけを示す矢印と、因果やデータの流れを示す矢印を区別する。
- **PPTD-152** 各段階の説明は短くし、詳細手順は別ページまたは注記へ移す。

#### タイムライン

- **PPTD-153** 原則3〜6個の節目に絞り、日付の尺度を一貫させる。
- **PPTD-154** 完了、進行中、予定を色だけでなく、ラベルまたは形状でも区別する。
- **PPTD-155** 時間の長さを表現する場合は、位置と幅を実際の期間に対応させる。

#### ロードマップ

- **PPTD-156** 時期、成果、責任主体、依存関係のうち、意思決定に必要なものを選ぶ。
- **PPTD-157** 施策一覧と時間軸を混同しない。
- **PPTD-158** 長期になるほど詳細度を下げ、確度の違いを明示する。

#### バリューチェーン／スイムレーン

- **PPTD-159** 工程、主体、入出力のどれを軸にするか先に決める。
- **PPTD-160** レーン数と工程数を絞り、交差する接続線を避ける。
- **PPTD-161** 例外経路をすべて一枚へ詰め込まず、主要経路と分離する。

### 構造と分類

#### 2×2マトリクス

- **PPTD-162** 二つの軸を独立かつ具体的に定義し、方向と単位を示す。
- **PPTD-163** 四象限の名称を先に決め、配置結果に合わせて恣意的に変更しない。
- **PPTD-164** 項目が重なる場合は、ラベル配置、番号、別表を使って読めるようにする。

#### リスクマトリクス

- **PPTD-165** 発生可能性と影響度の定義、評価期間、閾値を示す。
- **PPTD-166** 高リスクだけでなく、対応策、担当、期限への導線を作る。
- **PPTD-167** 色の濃淡だけでリスク区分を伝えない。

#### ツリー／階層

- **PPTD-168** 親子関係、分解基準、階層の深さを一貫させる。
- **PPTD-169** 同じ階層の項目に重複と抜けがないか確認する。
- **PPTD-170** 枝が多い場合は、概要と詳細へ分割する。

### 証拠とアクション

#### 表／チャート＋インサイト

- **PPTD-171** 左または上に証拠、近接する位置に解釈を置く。
- **PPTD-172** インサイトはグラフの再説明ではなく、差、原因候補、含意、判断のいずれかを示す。
- **PPTD-173** 強調箇所とインサイトの語を対応させる。

#### ケーススタディ

- **PPTD-174** 背景、実施内容、結果、適用条件を区別する。
- **PPTD-175** 結果には期間、母数、比較基準、出典を付ける。
- **PPTD-176** 一事例を一般法則として断定しない。

#### 推奨事項／アクション

- **PPTD-177** 推奨、理由、担当、期限、最初の一歩を必要な範囲で示す。
- **PPTD-178** 「検討する」「推進する」だけで終わらせず、判断または行動を具体化する。
- **PPTD-179** 未確定事項、依存関係、残存リスクを隠さない。

## 情報量の上限を判断する

次は固定仕様ではなく、初期設計の目安である。テンプレート、画面比率、投影距離、文字量、データ密度、アクセシビリティ要件に応じて、レンダリング結果を見て調整する。

| 要素 | 初期上限の目安 | 超えた場合の第一対応 |
|---|---:|---|
| 主要な視覚ブロック | 2〜4 | 主従を付けるか分割する |
| KPI | 2〜4 | 最重要だけ本文へ残す |
| 比較対象 | 2、必要時3 | 評価表または別ページへ移す |
| プロセス段階 | 3〜5 | 概要と詳細へ分ける |
| タイムラインの節目 | 3〜6 | 時期単位で分割する |
| 2×2の象限 | 4 | 別の分類軸を使う |
| 円・ドーナツの区分 | 5前後 | 棒または表へ変更する |
| 棒グラフの主要カテゴリ | 6前後 | 上位項目へ絞る |
| グラフの主要系列 | 3前後 | 小分けグラフまたはページ分割 |
| 主要な表の行 | 5〜7 | 要約行と詳細表へ分ける |
| 画像の主役 | 1 | 複数必要ならグリッドの理由を示す |

- **PPTD-180** 上限を超えた場合は、文言短縮、重要度整理、要素削減、ページ分割、レイアウト変更の順に検討する。
- **PPTD-181** 文字サイズ縮小と余白削減は最後の手段にする。
- **PPTD-182** 注記が多い場合は、主張の条件として必要な注記だけを本文近くへ置き、詳細を付録へ移す。
- **PPTD-183** 情報を削ると意味が変わる場合は削らず、ページを分割する。
- **PPTD-184** 同じ重要度の要素が多すぎる場合は、読み手の意思決定に基づいて優先順位を付け直す。

## デッキ全体のリズム

- **PPTD-190** 隣接ページで同じシルエットが続く場合、意図的な連続比較でなければ別の情報構造を検討する。
- **PPTD-191** レイアウトの多様性は装飾の変化ではなく、メッセージに合う情報構造の変化で作る。
- **PPTD-192** タイトル位置、外周余白、書体、色体系、フッターは安定させる。
- **PPTD-193** 密度の高い分析ページが続く場合は、要約、章扉、キーテイクアウェイで認知負荷を下げる。
- **PPTD-194** 二段組テキスト、カードグリッド、ダッシュボードを既定レイアウトにしない。
- **PPTD-195** 同じ構図を繰り返す場合は、比較可能性または作業効率という明確な目的を持たせる。

## チャートを設計する

チャート種類は、データ形式ではなく、読み手に答えてほしい問いから選ぶ。

| 問い | 推奨 |
|---|---|
| 時間とともにどう変わったか | 折れ線、必要に応じて縦棒 |
| どれが大きいか、順位は何か | 横棒、ドットプロット |
| 全体の内訳は何か | 積み上げ棒、区分が少ない場合だけドーナツ |
| 何が増減へ寄与したか | ウォーターフォール |
| 二変数に関係があるか | 散布図 |
| 分布はどうなっているか | ヒストグラム、箱ひげ |
| 目標に対してどこまで進んだか | 実績対目標の棒、ブレットチャート |
| 正確な値を参照する必要があるか | 表 |

- **PPTD-200** 一つのチャートで答える問いを一つにする。
- **PPTD-201** タイトルまたは近接する注釈で、読み取るべき結論を示す。
- **PPTD-202** 強調する系列を一つ決め、その他は背景化する。
- **PPTD-203** 同じ系列、状態、期間には同じ色を使う。
- **PPTD-204** 可能な場合は直接ラベルを使い、凡例と図の往復を減らす。
- **PPTD-205** 単位、期間、母数、定義、出典を表示する。
- **PPTD-206** 棒グラフは原則ゼロ基準にする。例外は切断を明示し、誤解を生まない場合に限る。
- **PPTD-207** 折れ線、散布図などで軸を切る場合も、変化を誇張しないか確認する。
- **PPTD-208** 3D、遠近、装飾的な立体円グラフを使わない。
- **PPTD-209** 区分が多い円グラフは、並べ替えた棒グラフまたは表へ変更する。
- **PPTD-210** 二軸チャートは関係を誤認させやすいため原則避け、必要なら尺度と理由を明示する。
- **PPTD-211** 合計、割合、平均との差、前年差を混同しない。
- **PPTD-212** 欠測、推計、予測、暫定値を見た目でも区別する。
- **PPTD-213** 数値とグラフの描画が一致するか、元データと照合する。

## 表を設計する

- **PPTD-220** 表を参照用、比較用、意思決定用のどれとして使うか決める。
- **PPTD-221** 列見出し、単位、期間、基準を明示する。
- **PPTD-222** 数値は桁と小数点を揃え、テキストと数値の配置を分ける。
- **PPTD-223** 読み手が比較する軸に沿って行または列を並べ替える。
- **PPTD-224** 最重要のセル、行、列だけを選択的に強調する。
- **PPTD-225** すべてのセルに濃い罫線を付けず、余白と弱い区切りで構造を示す。
- **PPTD-226** 数値が正確さを要求される場合、チャートへ置き換えず表を残す。
- **PPTD-227** 表が読めない密度になった場合は、要約表と詳細付録へ分ける。

## 画像とアイコンを使う

- **PPTD-230** 画像は理解、証拠、状況、感情、ブランドのいずれかを担う場合に使う。
- **PPTD-231** 装飾のためだけに内容と無関係な写真を置かない。
- **PPTD-232** 配置前に解像度、アスペクト比、被写体位置、トリミング余地を確認する。
- **PPTD-233** テキストと画像を並べる場合は、被写体の向きと余白がテキスト側へ視線を導く素材を選ぶ。
- **PPTD-234** 同じ画像を背景以外で繰り返し使わない。
- **PPTD-235** 写真、イラスト、3D、線画、アイコンのスタイルを不用意に混在させない。
- **PPTD-236** 画像上の文字は、オーバーレイ、背景処理、配置変更によって十分なコントラストを確保する。
- **PPTD-237** 画像を引き伸ばさず、必要な比率でトリミングする。
- **PPTD-238** アイコンは同じファミリー、線幅、塗り、視点で揃える。
- **PPTD-239** アイコンだけに意味を持たせず、誤解の可能性がある場合はラベルを付ける。
- **PPTD-240** 外部画像、生成画像、アイコンの利用条件と出典を記録する。

## 図解とコネクター

- **PPTD-250** 図解は、関係、流れ、階層、循環、境界の理解を文章より明確にする場合だけ使う。
- **PPTD-251** 単純な列挙を複雑な図へ変換しない。
- **PPTD-252** ノードの形、色、線種に意味を割り当て、その意味を一貫させる。
- **PPTD-253** コネクターはノードやラベルの背面に置き、文字を横切らないようにする。
- **PPTD-254** 線の交差、折れ曲がり、逆流を減らす。解消できない場合は構造またはページを分ける。
- **PPTD-255** 矢印の向き、開始、終了、双方向の意味を説明できるようにする。
- **PPTD-256** 図のラベルを短くし、詳細説明は図の近くまたは別ページへ置く。
- **PPTD-257** 円、歯車、パズル、電球などの慣用図形を、論理関係がないまま装飾目的で使わない。

## 既存テンプレートとPPTXを扱う

- **PPTD-260** 既存ファイルを直接上書きせず、ユーザーが明示した場合を除いて別名の作業コピーを作る。
- **PPTD-261** 全スライド、スライドマスター、レイアウト、プレースホルダー、テーマ色、テーマフォント、フッターを最初に調べる。
- **PPTD-262** 既存の代表的なレイアウトを複製し、プレースホルダーの役割を保ったまま内容を差し替える。
- **PPTD-263** マスター → レイアウト → スライドの継承を維持し、継承要素を個別図形へ平坦化しない。
- **PPTD-264** 一ページだけの変更はスライド、繰り返す変更はレイアウト、全体変更はマスターで行う。
- **PPTD-265** 会社のロゴ、機密区分、著作権表示、ページ番号を勝手に削除、移動、再作成しない。
- **PPTD-266** テンプレートにない新しい書体、色、角丸、影、アイコン体系を混ぜない。
- **PPTD-267** 既存資料の不整合を直す場合も、ブランドの意図と単なる偶然の差を区別する。
- **PPTD-268** マスターまたはレイアウトを変更した場合は、影響を受ける代表ページを再レンダリングして確認する。
- **PPTD-269** 内容がテンプレートへ収まらない場合、テンプレートを壊す前に内容短縮、分割、近い既存レイアウトへの変更を検討する。

## アクセシビリティと利用条件

- **PPTD-270** 色だけで状態、順序、正誤、増減を伝えない。
- **PPTD-271** 本文、図表、注記のコントラストを投影とPC閲覧の両方で確認する。
- **PPTD-272** 読み上げやキーボード操作が必要な環境では、オブジェクトの読み順と代替テキストを設定する。
- **PPTD-273** 文字を画像化しない。画像内文字が避けられない場合は代替説明を用意する。
- **PPTD-274** 海外展開や多言語化を想定する場合は、文言の伸長余地を確保する。
- **PPTD-275** 印刷用途では、余白、細線、淡色、背景全面色、裁ち落としの影響を確認する。
- **PPTD-276** オンライン会議用途では、小さな注記や複雑な表が共有画面で読めるか確認する。

## 視覚QA

PowerPointファイルの生成成功を、デザイン品質の合格とみなさない。必ずレンダリングした画像を確認する。

### 必須の確認順

1. **PPTD-280 全ページをレンダリングする**：最終PPTXから各スライドの画像を生成する。
2. **PPTD-281 個別確認する**：各画像を原寸相当で開き、文字、図、表、画像、フッターを確認する。
3. **PPTD-282 一覧確認する**：コンタクトシートまたはサムネイル一覧で、流れ、密度、反復、色、余白を確認する。
4. **PPTD-283 問題を記録する**：ページ番号、対象、症状、原因、修正を記録する。
5. **PPTD-284 生成元を直す**：レンダリング画像だけを加工せず、PPTXまたは生成コードの原因を修正する。
6. **PPTD-285 再レンダリングする**：修正したページだけでなく、影響範囲を再確認する。
7. **PPTD-286 合格判定する**：重大問題がゼロになってから完了とする。

### ページ単位のチェック

- **PPTD-290** タイトルが一行想定なのに折り返していない。
- **PPTD-291** 文字、図形、表、グラフ、画像がスライド外へはみ出していない。
- **PPTD-292** 文字切れ、隠れ、重なり、意図しない改行がない。
- **PPTD-293** 図形とコネクターがラベルを横切っていない。
- **PPTD-294** 外周余白、基準線、列幅、要素間隔が揃っている。
- **PPTD-295** 主要メッセージが最初に見え、強調が一箇所へ集約されている。
- **PPTD-296** 本文と注記が実際の表示条件で読める。
- **PPTD-297** 表の見出し、単位、桁、小数点、合計が正しい。
- **PPTD-298** グラフの軸、凡例、系列色、ラベル、出典がデータと一致する。
- **PPTD-299** 画像がぼやけ、変形、粗い切り抜き、不自然なトリミングになっていない。
- **PPTD-300** 未解決のプレースホルダー、サンプル文、仮数値、制作メモが残っていない。
- **PPTD-301** ページ番号、ロゴ、機密区分、出典がテンプレートどおりである。

### デッキ単位のチェック

- **PPTD-302** タイトルだけで論旨が通る。
- **PPTD-303** 章の区切りと現在地が分かる。
- **PPTD-304** 同じ意味に同じ色、書体、形、線種を使っている。
- **PPTD-305** 密度が極端に高いページまたは不自然に空いたページがない。
- **PPTD-306** 同じシルエットが理由なく連続していない。
- **PPTD-307** 比較ページで尺度、期間、基準、面積が公平である。
- **PPTD-308** 出典、注記、機密表示が必要なページに存在する。
- **PPTD-309** 元資料の内容、数値、引用、未確定性を保持している。
- **PPTD-310** 利用条件、対象読者、読後行動に合っている。

### 重大度

- **重大**：内容誤り、数値不一致、文字切れ、重なり、読めない文字、テンプレート破損、出典欠落、誤解を招く図表。納品禁止。
- **中**：整列ずれ、弱い階層、冗長、色の不統一、不自然な改行、画像品質不足。原則修正。
- **軽微**：意味を変えない微小な余白差、任意の装飾差。時間と効果を見て修正。

QAを実行していない場合、「確認済み」「崩れなし」「品質保証済み」と報告しない。

## 禁止する既定パターン

- **PPTD-320** 内容を小さなカード、ピル、バッジ、タブ、ボタン風要素へ機械的に分割しない。
- **PPTD-321** WebダッシュボードのようなUI表現を、操作性のないスライドへ無目的に持ち込まない。
- **PPTD-322** すべての要素を角丸枠と影で囲まない。
- **PPTD-323** テキストだけの二段組を、比較軸や関係がないまま既定レイアウトにしない。
- **PPTD-324** アイコン、矢印、色帯を、情報の意味を増やさない装飾として反復しない。
- **PPTD-325** 収まらない文章を極小文字で押し込まない。
- **PPTD-326** レイアウトの空白を埋めるために、根拠のない数値、画像、説明を追加しない。
- **PPTD-327** すべてのページを同じ構図にせず、すべてのページを別様式にもしない。
- **PPTD-328** 画像検索結果や生成画像を、利用条件、出典、内容整合性を確認せず使わない。
- **PPTD-329** 3Dグラフ、過剰なアニメーション、強いグラデーション、装飾的な影を品質の代わりに使わない。
- **PPTD-330** レンダリングせず、オブジェクト座標や生成ログだけで完成判定しない。

## レビューモードの出力

レビューでは、問題を好みとして断定せず、観察可能な症状、影響、修正案を対応づける。

| 項目 | 内容 |
|---|---|
| ページ | スライド番号または識別子 |
| 重大度 | 重大／中／軽微 |
| 規則ID | 該当する`PPTD-`識別子 |
| 症状 | 何が見えているか |
| 影響 | 読み手の理解、判断、可読性への影響 |
| 修正案 | 文言短縮、分割、整列、レイアウト変更など |
| 確認方法 | 再レンダリング後に何を見るか |

ユーザーが改善後のファイルも求めている場合だけ、修正を実施する。

## 実行モードの完了条件

次をすべて満たした場合だけ完了とする。

- **PPTD-340** 目的、対象読者、読後行動に合う。
- **PPTD-341** 一枚一メッセージと結論型タイトルが成立している。
- **PPTD-342** 事実、数値、引用、出典、未確定性を保持している。
- **PPTD-343** 既存テンプレート、マスター、レイアウト、ブランドを保持している。
- **PPTD-344** 情報量がレイアウト容量に収まっている。
- **PPTD-345** チャート、表、画像、図解が目的に合い、データと一致している。
- **PPTD-346** 日本語の文字化け、不自然な折り返し、極小文字がない。
- **PPTD-347** 全ページをレンダリングし、個別確認と一覧確認を終えている。
- **PPTD-348** 重大問題がゼロで、中程度の問題を修正または明示している。
- **PPTD-349** 元ファイルを保護し、最終成果物と一時ファイルを区別している。

最終報告は、成果物、代表的な変更、検証内容、残存する仮定または制約を短く示す。ユーザーが求めていない制作過程や内部メモをスライドへ追加しない。

## 社内ローカルAIによる統合・分割手順

この節は移植モードで必ず実行する。このファイル全体がチャットへ貼り付けられた場合、追加の説明がなくても「既存の社内PowerPoint作成Skillへ、レイアウト・デザイン規則を非コピー方針のまま統合する依頼」と解釈する。ただし、リポジトリや対象Skillが判別できない場合は、対象パスだけを確認する。

### 移植の目的

- このファイルを一度だけ手動コピーすれば移植できるようにする。
- 既存のPowerPoint生成、編集、レンダリング、テスト機能を壊さない。
- レイアウト・デザイン・視覚QAの規則だけを追加または強化する。
- 最終的なファイル数を可能な限り少なくする。
- 外部リポジトリのコード、文章、アセット、ブランド値をコピーしない。

### 移植前に調べる

1. **PPTD-400** リポジトリ内の指示ファイル、既存PowerPoint Skill、関連する参照ファイル、スクリプト、テンプレート、テストを列挙する。
2. **PPTD-401** 既存Skillのトリガー、ワークフロー、使用ツール、生成方式、レンダリング方式、QA方式を要約する。
3. **PPTD-402** 既存規則と本ファイルの各節を、同等、補完、競合、実装不能の四分類にする。
4. **PPTD-403** 競合時は、会社規程、既存テンプレート、既存生成エンジン、ユーザー要件を優先する。
5. **PPTD-404** 既存ファイルを削除または全面置換せず、最小差分で統合する。
6. **PPTD-405** 調査段階ではファイルを変更せず、対象と統合方針を確定する。

### ファイル数を決める

次の順に選ぶ。

#### 方式A：既存Skillへ一体化

既存の`SKILL.md`が許容サイズ内に収まり、実行時に全文を読み込んでも支障がない場合に選ぶ。

- 新規ファイルを増やさず、既存`SKILL.md`へ必要な節を統合する。
- 重複する規則は統合し、同じ意味を二重に残さない。
- 既存の実装手順を残し、本文の設計規則で補強する。
- 移植後も`PPTD-`識別子を残す。

#### 方式B：最小分割

一体化するとコンテキスト制限、ファイル上限、保守性、読み込み時間に明確な問題がある場合だけ選ぶ。原則として、既存ファイルを含めて次の三役へ分け、追加ファイルは最大二つにする。

1. `SKILL.md`
   - トリガー
   - 優先順位
   - 全体ワークフロー
   - レイアウト選択表
   - 参照ファイルを読む条件
   - 完了条件
2. `references/powerpoint-design-layout-ja.md`
   - 情報階層
   - グリッド、余白、色、タイポグラフィ
   - レイアウト・カタログ
   - チャート、表、画像、図解
   - テンプレート準拠
3. `references/powerpoint-visual-qa-ja.md`
   - 情報量の上限
   - 視覚QA
   - 禁止パターン
   - レビュー形式
   - 移植検査

既存Skillに同等の参照ファイルがある場合は、新規作成せずそこへ統合する。

#### 方式C：追加分割

社内AIまたは実行基盤の上限により方式A、Bが成立しない場合だけ選ぶ。分割理由、各ファイルを読む条件、総ファイル数を提示してから実施する。単に節が多いという理由では選ばない。

### 分割ルール

- **PPTD-410** 分割前にこのファイルを最初から最後まで読む。
- **PPTD-411** YAMLフロントマターは最終的なエントリーポイントの`SKILL.md`だけに置く。
- **PPTD-412** フロントマターには原則として`name`と`description`だけを置く。社内仕様が追加項目を必須とする場合はその仕様を優先する。
- **PPTD-413** 参照ファイルは`SKILL.md`から一階層で到達できるようにする。
- **PPTD-414** 各参照について「いつ読むか」を`SKILL.md`へ明記する。
- **PPTD-415** 同じ規則を複数ファイルへ複製しない。
- **PPTD-416** `PPTD-`識別子を変更、再採番、欠落させない。
- **PPTD-417** 社内の生成エンジン固有の操作は既存Skillに残し、本ファイルの一般原則で置き換えない。
- **PPTD-418** 外部参照元のコード、文面、数値定数、アセットを取得して補完しない。
- **PPTD-419** 一時的な元バンドルを製品Skill内へ重複保存しない。Git履歴または社内で許可された記録方法を正本にする。

### 統合時の必須成果

移植を実行したAIは、変更と一緒に次を提示する。

1. **PPTD-420 配置一覧**：変更したファイルと役割。
2. **PPTD-421 対応表**：元の節または規則IDが、どのファイルへ移ったか。
3. **PPTD-422 競合一覧**：既存規則を優先した箇所と理由。
4. **PPTD-423 欠落検査**：元ファイルと移植先にある`PPTD-`識別子集合を比較した結果。
5. **PPTD-424 参照検査**：`SKILL.md`から参照ファイルへのリンクが有効であること。
6. **PPTD-425 既存機能検査**：既存のPowerPoint生成、編集、レンダリング、テスト手順が残っていること。
7. **PPTD-426 非コピー検査**：外部コード、アセット、固有エンジン名、ブランド定数を追加していないこと。
8. **PPTD-427 ファイル数の説明**：方式A、B、Cのどれを選び、なぜ最小なのか。

### 規則IDの欠落検査

ローカル環境でコマンドを実行できる場合は、移植前後の`PPTD-`識別子を抽出し、集合差を確認する。実際のパスと利用可能なツールへ合わせて調整する。

```bash
rg -o 'PPTD-[0-9]{3}' source-skill.md | sort -u > /tmp/pptd-source.txt
rg -o 'PPTD-[0-9]{3}' path/to/skill -g '*.md' | sed 's/.*://' | sort -u > /tmp/pptd-target.txt
diff -u /tmp/pptd-source.txt /tmp/pptd-target.txt
```

差分がある場合、意図的に不採用とした規則を対応表へ記録する。説明のない欠落を残さない。`/tmp`を使えない環境では、許可された一時領域を使う。

### 移植後の動作確認

少なくとも次の四つの依頼を想定し、既存Skillが適切な規則を参照できるか確認する。実ファイル生成を伴うテストは、社内環境の安全規則と権限に従う。

1. 3個のKPIと結論を、一枚の経営報告スライドへ整理する。
2. 現状と改善案を、同じ比較軸のBefore／Afterとして設計する。
3. 12か月の推移データからチャートを選び、主要な変化を一つ強調する。
4. 既存会社テンプレートのマスターとレイアウトを保持して、文字切れを直す。

各ケースで、レイアウト選択、情報量調整、テンプレート優先、日本語改行、レンダリング後の視覚QAへ到達できれば合格とする。
